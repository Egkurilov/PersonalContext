# Контракты данных, алгоритмы и проверка

**v1.3:** дополнительные нормативные схемы memory/goals/candidates/recommendations/feedback/public research, API, scoring, governance и eval находятся в [INTELLIGENCE.md](INTELLIGENCE.md). Все новые записи используют тот же SQLite single writer, policy/expiry/tombstones, FTS5/NumPy и durable jobs. Обычные derived records не переживают evidence; подтверждённые пользователем snapshots регулируются явно выбранным scope/retention и каскадным privacy delete/revoke. Внешний fetch только выделенным opt-in public research broker, не ассистентом или ingestion.

## Event envelope v1
JSON, versioned JSON Schema + OpenAPI; UUIDv7 или UUIDv4, ISO UTC timestamp, original timezone IANA, duration ms integer/null; server clock separately. Example (synthetic):
```json
{"schema_version":1,"event_id":"018f0010-0000-7000-8000-000000000001","device_id":"demo-device","source_id":"demo-browser","source_event_key":"local-seq-42","kind":"web_active","started_at":"2026-01-01T12:00:00Z","ended_at":"2026-01-01T12:02:00Z","duration_ms":120000,"observed_at":"2026-01-01T12:02:01Z","timezone":"UTC","granularity":"interval","quality":"measured","policy_version":3,"consent_scope":"metadata","payload":{"domain":"example.org","url":"https://example.org/article","title":"Synthetic article","foreground":true},"provenance":{"collector":"browser","collector_version":"1.0.0","import_id":null}}
```
Kinds: app_active, idle, lock, web_visit, web_active, media_play, shared_item, document_reference, imported_visit, note, ocr_text (opt-in). Granularity point/interval; aggregate reserved for future schema version, reject it in v1; quality measured/imported/estimated/unknown. Point duration null; future aggregates must never convert to interval. Unknown duration not zero. Content body stored separately, referencing permitted event and hash, redact prior to persistence. Allowed metadata explicit schema per kind (app id/display label, domain, safe URL without userinfo/query/fragment, sanitized title, media id/author, normalized interval). Unknown keys rejected; bounded title 512 chars, content ≤16KiB after extraction, batch max 100/1MiB. No tokens, form fields, clipboard, keystrokes, audio/pixels. Sensitive patterns and deny policy before local spool + server defensive filter; reject content if consent/policy invalid. Non-HTTP protocols excluded by default. Default URL normalization canonical host IDNA lowercase, strip credentials/query/fragment, remove default port; no untrusted URL fetch. Validate start<=end, max interval 15min (split), no negative duration; >5min future clock flag quarantine safe metadata or reject; never infer absent end. Policy version, capability and provenance mandatory. Device timezone for local display; group wall-clock date by selected user timezone, DST tested.

## Storage
devices(id, owner, status, public_key/token_hash, last_seen, capabilities, config_rev); sources(id, device_id, type, enabled, scope, policy_rev, freshness, cursor); policies(version, allow/deny, capture modes, expiry); events(id, source_id, event_id unique, source_event_key unique within source, body_hash, kind, timestamps, granularity, payload_min, quality, expiry_at, consent); contents(id, event_id, sanitized_text, hash, lang, expiry); sessions(id, source/device, kind, interval, quality, event links); materials(id, canonical_key, title, first/last_seen, kind); material_events; chunks(id, content_id, version, index, text, expiry); chunk_embeddings(chunk_id, model_version, dimension, embedding_blob, expiry, UNIQUE(chunk_id,model_version,dimension)); topics(id, stable slug/name/aliases, status, user_override); topic_evidence(topic, event/material, confidence, type, model_version, derived_at); topic_edges(source_topic,target_topic,type,weight,valid_from/to,evidence); topic_snapshots(topic, period, score, confidence, coverage, delta, version, evidence); projects, knowledge_items, explicit_intentions, hypotheses, tags, overrides; jobs(type, idempotency_key unique, status, retry_at, attempts, lease_until, payload references); deletion tombstones, audit(event_type, actor, target_id, status, timestamp, correlation_id). Foreign keys and cascade/explicit cleanup, SQLite WAL; indexes (owner,time), (source,event key), FTS5 virtual table + versioned float32 BLOB vectors; no GIN/pgvector/partitioning; no personally identifying metric labels. All derived queries respect expiry/tombstone and access before candidate ranking.

## SQLite persistence and execution contract (ADR-011)
Use local on-disk SQLite only. WAL, foreign_keys=ON per connection, busy_timeout=5000, synchronous=FULL, single writer thread with bounded queue, separate readers, short transactions. SQLAlchemy Core and Alembic batch migrations, schema version/backup before migration; SQLite-compatible UUID TEXT, UTC timestamps normalized ISO UTC or integer epoch, JSON TEXT validated by application, BLOB embeddings; no PostgreSQL-specific SQL. Insert event+job in same transaction, ack only after successful COMMIT. Single-process lease claim and retry atomic via BEGIN IMMEDIATE and conditional update; lease recovered on app restart; never hold DB transaction across inference or network. Local Windows collector uses the same in-process validation/writer, no second spool DB. Browser offline queue retains sanitized events until durable ack; 72h tests for browser, local shutdown gaps explicitly shown.
FTS5 unicode61 and BM25 with synchronized insert/update/delete (verify FTS shadow cleanup); exact normalized little-endian float32 embeddings stored by chunk_id/model_version/dimension. Candidate authorization filters, expiry and tombstones applied in SQL before lexical/vector ranking. Use NumPy batched dot-product (e.g. 2048/4096 vectors per block), bounded CPU threads and stable top-k; no mix of model versions/dimensions, reject NaN/Inf/zero, cancel/deadline, final live permission recheck, lexical fallback. RRF merges dedup material results. Startup check FTS5 compiled into packaged SQLite. No external vector DB/index dependency. If measured target fails, ADR required for a local acceleration index. No remote DB or sync-folder placement.
SQLite Backup API, encrypted backup with tombstones/manifest, restore integrity_check + migrations. Delete derived rows and FTS entries, secure_delete and safe checkpoint/truncate WAL/compaction as required; no forensic guarantee for SSD/snapshots. Local ACL, recommend BitLocker, secrets DPAPI; SQLite file not intrinsically encrypted. See [ADR-011](adr/011-native-windows-python.md).

## API v1
- POST /api/v1/auth/bootstrap, /login, /logout, /rotate; cookie/CSRF; GET /me. Session rotation requires the current session, CSRF and Origin, replaces both secrets atomically and preserves the original expiry.
- GET/POST /api/v1/network/private/config: local owner-only review and preparation of a disabled HTTPS candidate; POST requires Origin, CSRF and revision. No passphrase is returned. This endpoint does not activate network access.
- POST /api/v1/network/private/firewall/check: local owner-only read-only snapshot assessment, with Origin and CSRF. Its result is diagnostic and does not activate network access.
- POST /devices/pairing-codes (owner), POST /devices/enroll (code), POST /devices/{id}/revoke, GET /devices and /sources; PATCH /sources/{id} pause/scope; GET /device/config, POST /device/heartbeat (device bound).
- POST /ingest/batch (device auth; envelope[]), per-event result accepted/duplicate/rejected with code; transaction event+outbox before ack; same event_id & hash = duplicate, same key different payload = conflict 409 per item; no echo raw content. Retry only transient/429/5xx with exponential backoff+jitter; accepted/duplicate only removed from browser offline queue; permanent reject counted and cleared securely. Status for revoked/paused/expired. Idempotency keys for jobs and imports. Pagination cursor stable (time,id), 100 default max 500.
- POST /imports/preview, POST /imports, GET /imports/{id}; size quotas, bounded parser, zip slip/zip bomb, no arbitrary remote URLs, selected fields and preview count/dates/errors before consent. Streaming, checkpoint; delete uploaded temp after parse; import id based on content hash+source and version.
- GET /timeline?from&to&device&source&kind&cursor; GET /events/{id} (safe subset), /materials/{id}; /overview?period&tz; /topics, /topics/{id}, /topics/{id}/evidence, /graph?period&limit; PATCH /topics/{id} user override; POST /topics/merge,/split with validated lineage; /projects and /knowledge CRUD; /insights.
- POST /search {query,from,to,source,topic,limit}; results with permitted evidence ids and score/version; POST /assistant/query {question,filters}, answer + citations + confidence/no_evidence; no autonomous tool calls, no arbitrary URL access. 
- GET/PATCH /privacy/policy, POST /privacy/pause, /privacy/delete/preview, /privacy/delete (scope + confirmation token), GET /privacy/jobs/{id}, POST /privacy/export, GET /audit, retention config; backup CLI only authorized admin.
- GET /healthz,/readyz (no sensitive info), authenticated /diagnostics, /metrics internal.
Errors RFC9457 style sanitized machine code, correlation ID, retry semantics; version contract snapshot tests. API filter scope applied server-side, not only frontend. Use explicit scopes for MCP vs device ingestion vs owner. Loopback HTTP default with strict Host/Origin/CSRF/session controls; optional private HTTPS only, see ADR-011.

## Normalize/sessionize/deduplicate
1. Sort by event timestamp with source key; split at idle/lock/sleep/resume, day boundaries (display), policy change; close intervals on heartbeat expiry with quality estimated, never extend beyond last proven sample + bounded heartbeat 15s. Use monotonic durations on device; handle sleep/DST/clock reset. Merge adjacent same kind/resource ≤5s gap only if no idle/lock/change; record original evidence. Browser active and app foreground same device: browser more specific, subtract overlap from generic app. Media playback inside foreground browser interval not additional active time; separate watch metric. Across devices: per-device measured totals and union wall clock; label concurrent. History import same canonical resource + timestamp within tolerance + source provenance → material association, not second active duration. Don't erase independent visits; unknown duration null. No iOS aggregates in v1; no fabricated timing for excluded sources. Reprocessing is deterministic, versioned, affected day recomputed; late event updates only relevant partitions. 
2. Canonical resource key: source type+safe normalized URL/video id/file stable local reference hash; cross-source materials merge only high confidence exact identifiers, preserve multiple evidence. Never hash sensitive forbidden payload as a retention workaround. Duplicate imports no double counting. 
3. Extraction: selected content from allowlisted DOM main/article/readability, sanitized text, remove scripts/forms/hidden content, chunk ~400 tokens with 60 overlap; cap and language detect. No fetch behind auth. Store source timestamp and permission, model version.
4. In-process asyncio scheduler + durable SQLite job lease with retry bounded (5 attempts, backoff up to 30min), DLQ metadata only, safe requeue after fix; job idempotency key (event/model/pipeline/version), outbox same SQLite transaction as ingestion, claim with single-writer BEGIN IMMEDIATE, release lock before model call. Rebuild from unexpired permitted events, no resurrection. Local LLM strict JSON Schema {topics:[{label,confidence,evidence_span}],entities,activity_type,summary,possible_intent,confidence}; validate references, cap topics ≤5, reject hallucinated citations/invalid JSON, retry bounded; model receives minimized text as untrusted data, no tools. No sensitive inference. Model version changes create versioned embeddings, background reindex and atomic switch, lexical fallback until ready.

## Interest graph and scoring v1 (deterministic)
Evidence is not endorsement. Use per-topic weighted event contributions:
- duration factor d=min(1,sqrt(active_seconds/600)) for measured interval; point visit default 0.15; explicit saved note 1.0; unknown duration not fabricated; no aggregate collectors in v1.
- source reliability r: explicit note/share 1.0, active content 0.85, active title only 0.55, imported visit 0.25, OCR 0.6. Topic classification confidence c in [0,1]; c<0.55 not scored (pending review). Multiply type weight w (active reading/play 1, brief visit 0.25, obligation tag 0.2); clamp; exclude idle/private/blocked entirely.
- collapse same resource/topic/day by max contribution (repeat count separately), per-topic daily cap 3; avoid refresh loops. S_h(t)=sum daily capped evidence * exp(-ln(2)*age_days/h). h=7 and 30 days. interest=round(100*(1-exp(-(0.6*S7+0.4*S30)/4))); delta vs 7 days prior, trend growing/declining if abs(delta)>=10 else stable; emerging if first_seen≤7 days and score≥20; stable if evidence≥3 distinct days over 30d. Pin/hide/rename/merge/split are user overrides, do not artificially change measured score; pin display order, hide removes from recommendations/search topic results as configured, not delete evidence unless explicit purge. Confidence separate from strength: weighted mean c*r, multiplied by min(1, distinct_days/3), label low/medium/high; coverage from healthy opted sources, missing sources flagged, not zero interest.
- Edges: co-occurrence of topics in same permitted material/session, min 2 distinct materials or manual link; weight Jaccard over dedup evidence sets, type cooccurrence/project/alias/manual, evidence list, valid time interval, threshold 0.1; never claim causality. Build stable IDs using aliases and similarity threshold calibrated by eval; ambiguous candidate pending review; split/merge maintain lineage and never erase user overrides. Top graph ≤100 nodes default, max 500 and expand.
- Snapshots daily user timezone + on-demand after late ingest/delete; version algorithm, expose explanation top evidence contributions, last_seen, confidence, score history, trend. Recalculate from valid event evidence after purge/expiry. Topic with zero evidence and not user-created disappears; user-created empty topic labeled manual. 
- Hypotheses/intentions explicitly distinguished, only confirmed by user becomes intention. Project mapping explicit alias/rules plus model suggestions requiring confirmation; generic activity not auto-assigned. Insights use facts from snapshots and evidence; local recommendations use saved materials and related topics, no web browsing by default.

## Quality / test design
Unit: schema, URL/token sanitization, policy precedence (deny wins), math, date/DST, event union, graph stable ids/overrides. Integration: real on-disk SQLite WAL+FTS5/NumPy, transactional outbox, dedup, crash/lease recovery, migration, purge across derived/index/cache, restore tombstones. Contract: API/OpenAPI+JSON schema fixtures, source version compatibility. UI E2E (Playwright): onboarding, consent, source states, real persisted events→timeline→topic detail→correction→search→MCP/Obsidian→delete→no results; mobile 360px, keyboard/axe. Platform: Windows app switch, lock/sleep, Chrome/Edge focus + incognito, optional Chrome macOS browser-only smoke, mobile web viewport, no Apple-specific collector prerequisite. Local model eval: ≥200 labeled synthetic/public licensed RU/EN items (≥50 Russian), split train/tune vs holdout, reproducible seed and version; macro F1≥0.75 topic labels, retrieval precision@5≥0.8, citation validity 100%, no-evidence abstention 100% on test prompts, zero leakage on sensitive/adversarial fixtures. Manual review false interest (work vs actual preference), no inference of sensitive traits. Prompt injection fixture 'ignore prior instructions' treated as content, not action. Performance: synthetic 900k events/100k chunks/1000 topics benchmark and 72h offline simulation; publish hardware, p50/p95, memory and error counts without user data. Test acceptance failures block release or documented OS capability fallback only; no mock success.

## Схемы состояния приложения

Общие JSON Schema для ответов `/healthz` и `/readyz` находятся в `schemas/` и генерируются командой `.venv/Scripts/python scripts/generate_schemas.py` из моделей приложения. Проверка тестирует оба успешных ответа, состояние недоступности и совпадение опубликованных схем с моделями. Это контракты состояния приложения. Схема событий и их полей остаётся отдельной незавершённой частью реализации.

Компоненты `event-id`, `event-kind`, `event-quality` и `event-timing` в `schemas/` задают общие типы и ограничения из раздела Event envelope v1. Они предназначены для композиции будущей полной схемы события. Схема `event-timing` проверяет отдельный объект из двух полей, поэтому для плоской оболочки нужно включить её свойства и условное правило в общую схему. Проверка только этих компонентов не подтверждает допустимость payload, согласие, доступ источника, временные границы или другие правила приёма.

`event-temporal` добавляет UTC timestamps в ограниченном RFC 3339 формате (`Z` или `+00:00`, до 128 символов), необязательный по значению `ended_at` и точную проверку порядка и предельной длины интервала в модели Python. Схема JSON описывает структуру и формат, но сама не выражает сравнение двух timestamps; проверка календарной даты требует включённого format checker. Контроль будущего времени относительно часов сервера, сопоставление duration и policy/consent остаются ответственностью будущего приёма событий. Компонент не подключает сбор или ingestion.
