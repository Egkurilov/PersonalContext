# PC-002: сопряжение устройств

Владелец с действующей сессией и CSRF выпускает одноразовый случайный 256-битный
код для явно выбранных прав `ingest`, `heartbeat`, `config`. Код действует пять
минут; одновременно допускается не более восьми действующих кодов. В SQLite
хранится только SHA-256 кода и отпечаток текущего хеша владельца. Смена пароля
владельца делает неиспользованные коды недействительными. Код и права нельзя
записывать в логи или в DOM; API возвращает код только владельцу.

При enrollment код расходуется и случайный идентификатор UUIDv4 вместе с
хешем нового 256-битного токена записываются в одной транзакции single-writer.
В случае отката код остаётся доступен, а устройство не создаётся. Ответ с
токеном возвращается после commit. Повтор, истечение, неверные часы и
повреждённые данные отклоняются; попытки enrollment ограничены пятью за пять
минут с сохранением состояния после перезапуска. Клиент обязан хранить токен
в OS vault или изолированном безопасном хранилище расширения, не в page script,
DOM, localStorage, логах или URL. Реальных клиентов эта задача пока не создаёт.

Права представлены маской: `ingest=1`, `heartbeat=2`, `config=4`. Проверка
требует совпадения токена и именно того UUID устройства, на которое выдан
токен, а также разрешения на конкретное действие. Отзыв владельцем через
сессию и CSRF немедленно делает последующие проверки отрицательными. Будущий
ingestion обязан выполнять проверку и запись одной операцией
writer внутри `BEGIN IMMEDIATE`; отдельная ранняя проверка не защищает от
гонки с отзывом. Текущие API создают код, выполняют enrollment, возвращают
список, отзывают устройство и принимают heartbeat, но не включают сбор и не
принимают события. Heartbeat проверяет привязку и право в одной транзакции с
обновлением `last_seen`; откат часов и отзыв приводят к отказу.

Зарегистрированных Chrome extension origins пока нет: общий middleware
отклоняет неизвестный Origin, а enrollment без Origin предназначен для
локального клиента. Полноценное расширение потребует отдельного явного
allowlist и защищённого хранилища. Тесты привязки, replay, TTL, отзыва,
транзакционного отката и негативных прав используют синтетические данные.
T02 целиком не выполнен до подключения авторизованного ingestion и политики.

Миграция `0007` создаёт таблицы pairing и devices. Существующая БД сохраняется
в DPAPI backup перед миграцией; откат — восстановление проверенной копии в
новый файл по README. Восстановление более старой резервной копии может вернуть
уже отозванные токены: после восстановления их необходимо повторно отозвать
и перевыпустить. Интерактивная проверка сопряжения устройства не выполнялась.
