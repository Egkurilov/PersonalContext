# PC-002: внутреннее хранилище сессий владельца

Миграция `0005` добавляет сессии с независимыми случайными 256-битными
значениями session и CSRF. В SQLite хранятся только SHA-256 этих значений,
хеш текущей учётной записи и времена выпуска/истечения. Время жизни — 30 минут;
не более 16 действующих записей. Устаревшие записи удаляются при выдаче новой
сессии, активные сессии при достижении лимита не вытесняются.

`create_session` — внутренний примитив: вызывать его только после успешной
проверки пароля и ограничения частоты. Он повторно сверяет хеш владельца в
`BEGIN IMMEDIATE`, чтобы параллельная смена учётных данных не создала сессию
по устаревшему паролю. Смена хеша владельца делает существующие сессии
недействительными. Logout должен вызвать `revoke_session` после авторизации.
Создание и отзыв проводятся через single-writer; секреты выдаются после commit.

`session_active` проверяет чтение, `authorize_mutation` требует CSRF и уже
открытую транзакцию. Для изменения данных авторизацию и само изменение нужно
выполнить в одном `BEGIN IMMEDIATE` на writer: иначе отзыв может произойти
между проверкой и записью. Ни одно из этих правил ещё не подключено к API.

Нет готового login/logout, cookies, CSRF transport, rate limit или проверки
Origin/Host для новых endpoint. Не логировать секреты, не помещать их в URL,
DOM или localStorage. Перед миграцией существующей БД создаётся DPAPI backup;
при откате восстановить проверенную копию в новый файл по инструкции README.
Downgrade удаляет сессии и сам по себе не восстанавливает прежние данные.
