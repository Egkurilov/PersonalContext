# PC-002: журнал безопасности

Миграция `0009` добавляет журнал с фиксированными полями: тип события, роль
(`owner`, `device`, `local`, `system`, `anonymous`), статус, UTC-время и
случайный UUID корреляции. Нет URL, текста, IP, кода сопряжения, хешей, токенов,
имён источников или идентификаторов устройств; `target_id` в API всегда `null`.
Типы и роли ограничены перечнями на уровне кода и SQLite. Повреждённая запись
не возвращается клиенту: API отвечает общей ошибкой без её содержимого.

Успешные bootstrap, login/logout, выдача и использование кода сопряжения,
отзыв устройства, изменение и пауза политики и восстановление копии записываются
в той же транзакции, что и операция. При сбое записи операция откатывается.
Неуспешные ограниченные rate limiter попытки входа и enrollment фиксируются как
`denied` с ролью `anonymous`, без введённых данных; запросы после исчерпания
лимита не создают неограниченный поток записей. Не все ошибки API и CSRF пока
аудируются. Восстановление копии со схемой до `0009` не может записать событие
restore в ещё не существующую таблицу.

`GET /api/v1/audit` доступен только сессии владельца, не кэшируется и возвращает
не более 100 записей за страницу с cursor `(timestamp,id)`. По умолчанию записи
старше 90 дней исключаются из выдачи и удаляются при записи, запуске и далее
ежечасно; в отсутствие новых событий физическое удаление может задержаться до
часа. Сбой очистки делает приложение неготовым к работе. Часы ОС используются
для срока хранения, поэтому их большие скачки могут изменить момент очистки.
Текущая версия не отображает журнал в интерфейсе.

До включения collectors необходимо также обеспечить немедленную локальную
паузу при недоступной или переполненной БД: сейчас ошибка транзакционной записи
аудита не позволяет подтвердить сохранение паузы. Сбор в текущей версии выключен.
