# PC-002: внутреннее ограничение частоты авторизации

Миграция `0006` добавляет локальное состояние для трёх действий: `owner_login`
(не более пяти попыток за скользящие 60 секунд), `owner_bootstrap` и
`device_enroll` (по пять за скользящие 300 секунд). Лимит общий для процесса и
переживает перезапуск: отдельно для каждого действия хранятся только времена и
водяной знак часов, без IP, идентификаторов устройств, кодов и других данных.
Ограничение глобальное и может временно отказать владельцу при атаке; это
консервативный выбор до разработки более детальной модели.

`consume_attempt` выполняется через single-writer и `BEGIN IMMEDIATE` до
проверки кода или запуска Argon2. Неизвестное действие, некорректное время,
повреждение состояния и обратный скачок часов приводят к отказу. Повторное
включение возможно после восстановления времени; неопределённую длительность
ожидания нельзя представлять как успешную попытку. Только разрешённые попытки
записываются в ограниченный список. Вызывающая сторона обязана дождаться commit.

Bootstrap и login через loopback API используют этот механизм и отвечают `429`
при исчерпании лимита. Device enrollment ещё не подключён. Перед миграцией старой
БД создаётся DPAPI backup; для отката восстановить проверенную копию в новый
файл. Downgrade удаляет счётчики и способен сбросить лимит — не использовать
его как обычный способ восстановления авторизации.
