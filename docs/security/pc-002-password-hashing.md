# PC-002: хеширование паролей

Внутренний компонент `password_hash` создаёт Argon2id-хеш со случайной солью
16 байт и параметрами v=19, m=19456 KiB, t=2, p=1, длина хеша 32 байта.
Параметры соответствуют минимальной конфигурации [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
Пароль при создании содержит не менее 12 символов и не более 1024 байт UTF-8;
пробелы и Unicode не нормализуются. Неверный ввод не выводится в сообщениях.

Проверка принимает только текущий профиль параметров и ограниченный размер
кодированной строки, чтобы повреждённый хеш не задавал произвольные затраты
ресурсов. Для смены профиля потребуется поддерживаемая миграция с ограниченным
списком старых параметров и rehash после успешного входа.

Миграция `0003` добавляет единственную запись хеша владельца; внутренний
single-writer отклоняет неподдерживаемые хеши и не перезаписывает уже созданную
учётную запись. Этот внутренний примитив не проверяет bootstrap-код и не должен
вызываться из API до реализации проверки. Перед миграцией существующей базы
создаётся DPAPI backup; откат выполняется восстановлением проверенной копии в
новый файл по инструкции README. Удаление таблицы через downgrade уничтожает
находящийся в ней хеш и не заменяет резервное копирование.

Это не готовая авторизация: bootstrap, подключение хранилища к API, сессии,
CSRF, ограничение частоты и аудит ещё не реализованы. Будущий обработчик должен ограничить частоту
до проверки пароля, выполнять Argon2 вне event loop и вне блокировки SQLite,
ограничивать число одновременных вычислений и не логировать пароль или хеш.
Внутренний `PasswordExecutor` выполняет hash/verify в ограниченном пуле из
1–4 потоков (по умолчанию 2), отклоняет запрос при занятости и удерживает слот
до фактического завершения работы даже после отмены ожидающего запроса. Пул
не подключён к API и сам по себе не является rate limit.
Фактическая доступность зависимости внутри frozen-сборки проверяется только
после подключения к работающему приложению.
