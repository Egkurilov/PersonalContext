# PC-001 — приёмка на чистой Windows 11 x64

Статус: **не выполнена**. Это инструкция для проверки, а не свидетельство её
успеха. Нужна отдельная одноразовая Windows 11 x64 VM или чистая тестовая
машина со стандартной учётной записью без прав администратора. Не использовать
основной пользовательский профиль и реальные данные. До начала убедиться, что
PersonalContext и его каталог `%LOCALAPPDATA%\PersonalContext` отсутствуют.

## Подготовка

1. Зафиксировать версию Windows и архитектуру, а также способ подтверждения,
   что на тестовой системе нет отдельно установленных Python, Node.js, Docker,
   WSL и PostgreSQL. Сам по себе пустой PATH этого не доказывает.
2. Передать на тестовую машину собранные `PersonalContext-Setup.exe` и его
   `.sha256` из проверенной сборки. Сравнить SHA-256 файла с контрольной суммой
   до запуска. Записать ревизию исходников и хеш установщика.
3. Работать под стандартным пользователем без запуска от администратора.
   Если защита Windows блокирует неподписанный файл или требуется повышение
   прав, зафиксировать блокировку; не обходить защиту ради прохождения теста.

Для сверки хеша можно выполнить `(Get-FileHash -Algorithm SHA256 -LiteralPath
$installerPath).Hash`, задав `$installerPath` для переданного файла. Сравнить
результат с содержимым переданного файла `.sha256`.

## Установка и обновление

1. Установить приложение через обычный интерактивный установщик. Проверить,
   что запрос повышения прав не возник и установка находится в профиле
   пользователя. Не разрешать сбор активности и не добавлять источники.
2. Запустить приложение. Проверить значок трея, открытие портала и ответы
   `/healthz` и `/readyz` на `http://127.0.0.1:17890`; убедиться, что
   интерфейс сообщает об отключённом сборе. Проверить, что слушающий TCP-порт
   процесса расположен только на loopback и нет отдельного порта БД или модели.
3. Создать в `%LOCALAPPDATA%\PersonalContext\data` текстовый файл-маркер с
   единственным словом `synthetic`. Пока приложение запущено, повторно
   установить ту же версию. Проверить штатное завершение старого процесса,
   запуск после установки, готовность и сохранность маркера. Эта проверка не
   подтверждает миграцию со старой схемы без отдельного синтетического fixture.

Для проверки портов в PowerShell можно получить PID через `Get-Process
PersonalContext`, затем выполнить `Get-NetTCPConnection -State Listen
-OwningProcess $appPid` для каждого PID приложения. Если стандартной учётной
записи недостаточно для этой проверки, отметить её как невыполненную.

## Удаление

1. Выполнить интерактивное удаление, выбрав **сохранить данные**. Проверить,
   что приложение удалено, а синтетический маркер сохранился.
2. Повторно установить и запустить приложение, затем выполнить интерактивное
   удаление, выбрав **удалить данные**. Только на одноразовой тестовой машине
   проверить отсутствие каталога PersonalContext и маркера.
3. Для каждого шага записать pass/fail, наблюдение и точную причину пропуска.
   Не публиковать имя пользователя, пути профиля, device ID, содержимое базы,
   журналы или реальные действия. Указать неподтверждённые пункты отдельно.

Успех этой проверки не заменяет gates PC-025, privacy lifecycle и приёмку
реальных источников. Не заявлять успех, если VM, интерактивный рабочий стол
или проверка отсутствия зависимостей недоступны.
